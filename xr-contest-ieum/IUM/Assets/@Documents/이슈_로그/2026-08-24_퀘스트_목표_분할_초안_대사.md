# 2026-08-24 · 퀘스트 목표 분할과 초안 대사

제작 공정 다섯 개를 `quest.json`의 퀘스트 그래프로 이관한 뒤, 확정된 퀘스트 디자인에 맞춰 목표를 분할한 작업에서 남긴 사항이다.

분할 결과는 먹매김 2개(`draw_first_line` → `draw_second_line`), 끌질 2개(`chisel_first_groove` → `chisel_second_groove`), 공포 조립 3개(`gongpo_first_piece` → `gongpo_lower_tier` → `gongpo_complete_all`)다. 톱질과 도리 설치는 단일 목표를 유지했다. 같은 신호 키를 나눠 쓰는 목표의 `amount`는 `ProcessSignalBus`가 키별 누적이고 `ProcessStep.Arm()`이 버스를 초기화하지 않으므로 개별 요구량이 아니라 **누계**로 적었다(1 → 2, 1 → 18 → 37).

분할로 새로 생긴 중간 성공 지점과, 원래부터 대사가 하나도 없던 공포 조립 구간에 대사를 채웠다. 같은 날 이어진 후속 작업에서 튜토리얼 대사를 전면 재작성하고 목표 진입 안내 대사 4종을 신설했다. 이 문안들이 이 세션의 미확정 항목이다.

## ISSUE-027 · 목표 분할·공포 조립·튜토리얼·목표 안내 대사가 기획 미확정 초안

### 추가분 · 튜토리얼 재작성과 목표 안내 층 (같은 날 후속 작업)

같은 날 이어진 작업에서 초안 범위가 넓어졌다. 아래 두 묶음도 **기획 확정본이 아니다**. 위 6종과 함께 확정 문안이 오면 교체한다.

**1. 튜토리얼 대사 전면 재작성 (24개 시퀀스, ISSUE-018 대상과 동일 범위)**

ISSUE-018이 남긴 튜토리얼 초안을 "다섯 공정의 예행연습"이라는 방향으로 다시 썼다. 시퀀스 ID와 줄 ID 규약, 화자, `blocksProcess`·`priority`·`interruptible`은 그대로 두고 `text`만 교체했으며, 줄이 늘어난 시퀀스는 `{시퀀스ID}_{N}` 규약을 이어 붙였다.

| 시퀀스 ID | 화자 | 줄 수 변화 |
|---|---|---|
| `tutorial_nojang_welcome` | 노장 | 4 → 4 |
| `tutorial_greeting` | 이음이 | 3 → 3 |
| `tutorial_look_intro` / `_retry` / `_success` | 이음이 | 2·1·1 유지 |
| `tutorial_move_intro` / `_retry` / `_success` | 이음이 | 2·1·1 유지 |
| `tutorial_turn_intro` / `_retry` / `_success` | 이음이 | 2 → 3, 1·1 유지 |
| `tutorial_point_intro` / `_retry` / `_success` | 이음이 | 2 → 3, 1·1 유지 |
| `tutorial_grab_intro` / `_retry` / `_success` | 이음이 | 3 → 4, 1·1 유지 |
| `tutorial_place_intro` / `_retry` / `_success` | 이음이 | 2 → 3, 1·1 유지 |
| `tutorial_ptt_intro` / `_retry` / `_success` | 이음이 | 2 → 3, 1 유지, 1 → 2 |
| `tutorial_complete` | 노장 | 2 → 3 |

조작키 표기는 기존 초안의 형식(`마우스 오른쪽 버튼`, `W A S D 키`, `Q 키`/`E 키`, `F 키`, `마우스 왼쪽 버튼`, `T 키`)을 그대로 유지했다. ISSUE-018이 지적한 대로 **조작키를 대사에 박아 둔 것 자체가 임시**이며, 별도 안내 UI가 생기면 키 이름은 대사에서 빼야 한다.

**2. 목표 진입 안내 대사 신설 (이음이, 4종)**

퀘스트 레벨 `introDialogue`(기획 원문)는 공정의 의미를 말할 뿐 "어떻게, 얼마나"를 말하지 않는다. 목표가 분할되면서 그 간극이 커져 objective 층에 안내 대사를 새로 넣었다. 각 시퀀스의 마지막 줄은 이음이를 불러 물어보라는 유도(F-013 PTT 경로)로 끝난다.

| 시퀀스 ID | 화자 | 배선 위치 | 비고 |
|---|---|---|---|
| `makmeok_obj1_intro` | 이음이 | `makmeok/draw_first_line.introDialogue` | 기준선이 둘이고 지금은 첫 번째라는 수량 맥락 포함 |
| `sawing_obj_intro` | 이음이 | `sawing/sawing_plane_work.introDialogue` | 기획 원문(`sawing_intro`)의 톱질 서사와 실제 구현(대패 왕복 스트로크)의 어긋남을 이 층에서 해소한다 |
| `chiseling_obj1_intro` | 이음이 | `chiseling/chisel_first_groove.introDialogue` | 홈이 둘이라는 수량 맥락 포함 |
| `gongpo_obj1_intro` | 이음이 | `gongpoPuzzle/gongpo_first_piece.introDialogue` | 전체 37개라는 수량 맥락 포함 |

`sawing_obj_intro`에는 요구 스트로크 수치를 적지 않았다. 요구량이 코드 상수가 아니라 `PlaneZone.requiredStrokes`·`SawZone.requiredStrokes`의 인스펙터 필드(기본값 3·5)라 씬 설정에 따라 달라지기 때문이다. 수치를 확정하면 문안에 넣을 수 있다.

`purlinInstall/install_first_floor_member`에는 신규 문안 없이 기존에 어디에도 배선되지 않던 기획 원문 시퀀스 `purlin_joint_intro`를 연결했다. 이 한 건은 초안이 아니라 원문 재활용이다.

## ISSUE-019 처리 경과

`ISSUE-019 · 공포 퍼즐 대사 없음`은 **미해결로 유지한다**. 이 세션에서 채운 것은 러너 배선에 필요한 초안이지 기획 확정 문안이 아니므로, 이슈가 요구하는 "기획 작성"은 아직 오지 않았다. 다만 "대사가 하나도 없어 구간 전체가 무음"이던 상태는 해소되었으므로, 남은 것은 문안 교체(ISSUE-027)뿐이라는 점을 함께 기록한다. 확정 문안이 도착해 교체하면 두 이슈를 같이 닫는다.

## ISSUE-028 · 튜토리얼 강제 시선 회전의 VR 안전성 미검증

| 항목 | 내용 |
|---|---|
| 발견일 | 2026-08-24 |
| 상태 | 미해결 |
| 위치 | `Assets/@Scripts/Quest/TutorialFlowDirector.cs`의 `BeginTurnToSpeaker`·`TurnRoutine`, `Assets/@Scripts/Player/ViewModule.cs`의 `SetLookDirection` |
| 관련 | ISSUE-007(컷씬 카메라 교체의 VR 안전성), `.claude/rules/개발환경_입력.md` |
| 증상 | 튜토리얼 인트로에서 노장의 첫 대사가 나갈 때 플레이어 시점을 약 1초에 걸쳐 노장 쪽으로 강제 회전시킨다. 데스크톱에서는 발화자를 놓치지 않게 하는 안내지만, HMD를 쓴 상태에서 시점을 코드가 돌리는 것은 대표적인 멀미 요인이다. 그래서 `XRSettings.isDeviceActive`가 참이면 회전을 생략하고 로그만 남기게 했다. |
| 영향 | 지금 깨지는 것은 없다. 데스크톱에서는 의도대로 동작하고 VR에서는 아무 일도 하지 않으므로, VR 플레이어는 노장이 어디 있는지 스스로 찾아야 한다. 첫 발화가 시야 밖에서 시작되면 누가 말하는지 모른 채 인트로가 지나갈 수 있다. |
| 조치 방향 | VR에서 주시를 어떻게 유도할지는 기획·실기기 검증 항목이다. 후보는 방향 지시 HUD, 노장 쪽 공간 오디오 강조, 암전 중 리센터 정도이며 어느 것도 확정되지 않았다. 실기기를 확보한 뒤 정한다. 데스크톱 회전 자체는 `ViewModule.SetLookDirection` 한 곳을 지나므로 방침이 정해지면 호출부만 바꾸면 된다. |
