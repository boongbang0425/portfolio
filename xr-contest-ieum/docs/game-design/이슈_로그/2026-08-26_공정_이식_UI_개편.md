# 2026-08-26 · 공정 이식·UI 개편 세션

GongpoScene 최신 공정을 Play 씬으로 재이식(자귀·배대패·Part 계열·작업대 포함, 도구 비주얼 교체), `MainPlayProcessBridge` 다중 존 대응, StartScene 개편(원형 플레이 버튼·모니터 영상 재생), 인게임 일시정지·옵션 UI를 `BoardRoot` 기반 `BoardHud`로 교체, 노장 영역 추종 구현을 진행한 세션이다. 이 과정에서 범위 밖으로 보고만 한 사항을 남긴다.

이 세션에서 처리한 기존 이슈: **ISSUE-025(해결)** — `PauseHud.prefab`은 8/24 커밋으로 이미 씬 배치·UXML 비활성까지 끝나 있었고, 이번 세션에서 `BoardHud.prefab`으로 다시 교체되었다.

## ISSUE-029 · 다중 존 도입 후 공정 완료 기준이 기획 미확정

| 항목 | 내용 |
|---|---|
| 발견일 | 2026-08-26 |
| 상태 | 미해결 |
| 위치 | `Assets/@Developers/RYU/ProcessIntegration/MainPlayProcessBridge.cs`, `Assets/@AddressableAssets/Data/Static/quest.json` |
| 관련 | ISSUE-030, `Assets/@Scripts/GongpoAssemble/Woodworking/Zones/` |
| 증상 | Part 계열 이식으로 Play 씬에 SawZone 4·InkLineZone 5·ChiselZone 17·PlaneZone 14·AdzeZone 4가 존재한다. 브릿지는 "임의 존 1개 완료 = 기존 단일 존 완료"로 의미를 보존했고, AdzeZone과 PlaneZone(톱 존 존재 시)은 퀘스트 신호에 연결되지 않는다. 먹매김·끌질 quest 목표 amount(각 2)도 존 수보다 훨씬 작다. |
| 영향 | 기존 퀘스트 흐름은 그대로 동작한다. 다만 "존 전부 완료"가 기획 의도라면 목표 수치와 브릿지 플래그 구조 변경이 필요하고, 자귀질·대패질을 공정으로 승격할지도 미정이다. |
| 조치 방향 | 기획 확정 후 quest.json amount 조정과 브릿지 카운터 확장. 자귀·대패 공정 승격 시 신호 키 신설. |

## ISSUE-032 · 팀원 신규 자산의 규약 이탈과 통합 주의점

| 항목 | 내용 |
|---|---|
| 발견일 | 2026-08-26 |
| 상태 | 미해결 |
| 위치 | `Assets/Scripts/`(Board3D 계열, 폴더 규약 이탈), `Assets/Scenes/SampleScene.unity`(팀원 테스트 씬), `Assets/Scripts/MouseRayTester.cs`, `Assets/@GameAssets/Prefabs/BoardRoot.prefab` |
| 관련 | `Assets/@Scripts/UI/World/BoardPauseMenu.cs`, ISSUE-026(앞면 축 추정과 동일 성격의 추정이 BoardHud에도 존재) |
| 증상 | ① 신규 스크립트가 `@Scripts` 구조 밖 루트 `Assets/Scripts/`에 있다. ② `MouseRayTester`는 레거시 Input API라 본 프로젝트(Input System 전용)에서 예외를 던진다 — 미사용 방치 중. ③ `Btn_Continue`·`Btn_Restart`·`Btn_Main`의 프리팹 onClick은 빈 상태이고 동작은 `BoardPauseMenu`의 코드 구독이 담당한다. ④ BoardRoot 판 앞면 축(+Z)은 추정값이다. |
| 영향 | 실행에는 문제없다. 다만 팀원이 나중에 프리팹 onClick 퍼시스턴트 콜을 채우면 이중 실행이 되고, 앞면 축 추정이 틀리면 메뉴가 뒤집혀 보인다(인스펙터로 교정 가능). |
| 조치 방향 | 커밋 전 폴더 위치·MouseRayTester 폐기 여부·onClick 배선 방식을 소유 팀원과 합의한다. |
